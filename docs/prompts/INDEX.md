# Промпты — карта

Готовые промпты для типовых сценариев. Открывайте нужный файл, копируйте промпт, подставляйте свои значения вместо `<ВОТ ТАКОГО>`, отправляйте Claude Code.

Каждый промпт — самодостаточный: содержит «когда использовать», «когда НЕ использовать», тело промпта и «что должно получиться».

## Карта по сценариям

| Сценарий | Промпт | Когда |
| --- | --- | --- |
| Только что развернули шаблон, нужно адаптировать под свой проект | [bootstrap-project.md](./bootstrap-project.md) | один раз в самом начале |
| Есть проект, но `business/` пустой / устаревший — нужно наполнить | [create-business-brain.md](./create-business-brain.md) | при первом наполнении или ревизии бизнес-контекста |
| Сел за проект, не помнишь где остановился — войди в контекст | [start-session.md](./start-session.md) | в начале каждой сессии |
| Закрываем день — обнови план, ретроспективу, бизнес-файлы | [end-session.md](./end-session.md) | в конце каждой сессии |
| Нечёткая идея — нужно превратить в план через интервью | [grill-idea.md](./grill-idea.md) | до создания плана крупной фичи |
| Создать план новой фичи по шаблону | [create-feature-plan.md](./create-feature-plan.md) | перед реализацией крупной фичи |
| Прогнать готовый план через критика | [run-critique.md](./run-critique.md) | сразу после создания плана |
| Добавить чистую функцию через TDD | [add-tdd-feature.md](./add-tdd-feature.md) | при разработке логики с понятным input → output |
| Починить баг по систематическому циклу | [debug-bug.md](./debug-bug.md) | при репорте бага |
| Визуальный обзор UI-экрана / макета | [visual-review.md](./visual-review.md) | перед сдачей UI или после правок |
| Деплой проекта на Vercel / Railway / Amvera | [deploy-project.md](./deploy-project.md) | перед первым прод-деплоем |

## Типовой день в шаблоне

Утро: `start-session.md` → понять где остановились.

День: один из специализированных:

- идея в голове → `grill-idea.md` → `create-feature-plan.md` → `run-critique.md`
- баг → `debug-bug.md`
- чистая логика → `add-tdd-feature.md`
- UI готов → `visual-review.md`
- хочу выкатить → `deploy-project.md`

Вечер: `end-session.md` → закрыть план, ретроспектива, бизнес-файлы.

## Связи с правилами и скиллами

Каждый промпт ссылается на конкретные файлы шаблона:

- Правила в `.claude/rules/` — что НЕ делать, какой формат соблюдать.
- Скиллы в `.claude/skills/` — как именно вести цикл (debug-bug → diagnose, add-tdd-feature → tdd, grill-idea → grill-me, bootstrap-project → project-bootstrap).
- Шаблоны в `plans/TEMPLATE.md` и `retrospectives/TEMPLATE.md` — структура планов и итогов.

Если промпт где-то противоречит правилу из `.claude/rules/` — выигрывает правило, а противоречие сообщите автору.

## Как добавить свой промпт

1. Один файл `docs/prompts/<глагол>-<объект>.md`.
2. Структура: «Когда использовать» → «Когда НЕ использовать» → «Промпт» (в `````) → «Что должно получиться».
3. Промпт пишите от своего лица к Claude. Указывайте конкретные файлы, которые надо прочитать.
4. Добавьте строку в таблицу выше.
5. Тестируйте: возьмите свой промпт, прогоните на реальной задаче, поправьте формулировки.
