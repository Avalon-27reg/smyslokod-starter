# Промпт: закрыть сессию

> Используйте в конце рабочей сессии, даже если работа не доделана. Checkpoint плана - память для следующей сессии, поэтому его обновление важнее всего остального.

## Когда использовать

- Закончили на сегодня и хотите оставить чистое состояние для следующей сессии.
- Что-то не доделали - нужно зафиксировать, где остановились.
- Узнали новое про проект - нужно перенести из чата в `business/`, пока не забылось.

## Промпт

```
Закрываем сессию.

1. Активный план в plans/:
   - обнови checkpoint (раздел 9): что сделано и чем проверено, незакоммиченные файлы плана, остаток, блокеры, израсходованные лимиты, следующий шаг, запущенные процессы;
   - фаза прошла Self-Audit (раздел 10), ревью и судью без блокеров - [x] у фазы; ревью ещё ждёт - так и запиши в checkpoint;
   - изменился подход - перепиши "Дизайн решений"; появились риски - добавь в "10 причин провала".

2. Узнали новое про проект - точечно обнови business/: ядро или раздел по .claude/rules/business-context.md. Новые термины - в CONTEXT.md. Покажи, что обновил.

3. Ретроспектива retrospectives/YYYY-MM-DD-<имя>.md по TEMPLATE.md: обязательно, если план закрыт; иначе - если в сессии был урок, который пригодится дальше.

4. В конце выдай ровно 4 строки:
   - Сделано: <короткий список>
   - Не сделано: <короткий список>
   - Следующий шаг: <одно действие>
   - Что обновлено: <plans/..., business/..., retrospectives/...>

Коммит - если его разрешает план или я прямо попросил, файлы поимённо; иначе незакоммиченные файлы - в checkpoint. Push - нет.
Не доделано - пиши "не сделано", без "pre-existing" / "out of scope" / "потом".
Ответы - на русском.
```

## Что должно получиться

- Checkpoint активного плана отражает фактическое состояние.
- Точечно обновлены `business/` и `CONTEXT.md`, если было что обновить.
- Ретроспектива - если план закрыт или был урок.
- 4-строчная сводка в чате.

## После

В следующей сессии напишите «продолжаем» (`start-session.md`): Claude сверит checkpoint с файлами и продолжит.
