# Промпт: bootstrap FULL — коммерческий продукт

> Используйте если делаете серьёзный коммерческий продукт: ПДн / платежи / несколько сегментов / команда 2+ / срок планирования 1+ месяцев. Если не уверены — берите [bootstrap-project.md](./bootstrap-project.md), он сам выберет режим.

## Когда использовать

Любое из:

- Коммерческий продукт с подписочной или транзакционной моделью.
- Сбор персональных данных (нужна Политика конфиденциальности и оферта).
- Несколько сегментов аудитории или несколько продуктов.
- Команда из 2+ людей.
- Срок планирования — 1+ месяцев.
- Уже есть реальные интервью / продажи / факты про рынок.

## Когда НЕ использовать

- Прототип на день / неделя → MINIMAL или LITE. Не тратьте 2 часа на интервью, если завтра проект может оказаться неинтересным.
- Не уверены в монетизации → сначала LITE, там есть шанс быстро понять «работает ли».

## Время и объём

- **90–120 минут**, 10+ вопросов (включая юрисдикцию, экономику, конкурентов).
- Заполняются **все 7 блоков** `business/` (или с пометками `🔲 заполнить:` где данных нет).
- План + **обязательный** прогон через субагент `critic` + первая ретроспектива.

## Промпт

```
Запусти скилл project-bootstrap (.claude/skills/project-bootstrap/SKILL.md)
сразу в режиме FULL. Auto-detect пропусти, я знаю что делаю
коммерческий продукт.

Алгоритм по разделу "Режим FULL" в SKILL.md:

1. Прочитай: CLAUDE.md, business/INDEX.md, plans/TEMPLATE.md,
   retrospectives/TEMPLATE.md, SKILL.md, и .claude/rules/business-context.md.

2. Задай мне все вопросы по одному за раз, с вариантами а/б/в/г где можно:
   - О каком проекте речь.
   - Целевая аудитория (один сегмент конкретно).
   - Боль (одна).
   - Формат: лендинг / SaaS / AI-агент / marketplace / другое.
   - Где деплой: Vercel / Railway / Amvera / ещё не решили.
   - Минимальный результат за сессию.
   - Бренд / тон / референсы.
   - Интеграции (LLM, платежи, БД, аналитика).
   - Стоп-критерий "хватит на сегодня".
   - Что важно НЕ трогать.
   - Юрисдикция / есть ли ИП-ООО / собираем ПДн.
   - Базовая экономика: цена и ориентировочный CAC.
   - Конкуренты (2–3 ближайших).

3. Обнови ВСЕ 7 блоков business/:
   - business/INDEX.md (актуализируй карту).
   - company/about, team, legal, values.
   - products/overview, pricing, product-1.
   - audience/avatar, segments, objections, journey.
   - goals/annual, quarterly, monthly, kpi.
   - economics/unit-economics, revenue, costs, forecast.
   - marketing/channels, competitors, content, funnel.
   - assets/brand-guidelines, copy-bank, testimonials.

   Где данных мало — пометки "🔲 заполнить:" с конкретным вопросом.
   Не выдумывай факты.

4. Обнови CLAUDE.md разделы 1, 2, 9. Файл должен остаться ≤ 200 строк.

5. Создай plans/YYYY-MM-DD-<имя>.md по plans/TEMPLATE.md
   с полным блоком "10 причин провала".

6. ОБЯЗАТЕЛЬНО прогони план через субагент critic
   (.claude/agents/critic.md). Если субагенты недоступны —
   сделай критику сам по тому же формату. Внеси правки в план.

7. ОБЯЗАТЕЛЬНО создай первую запись retrospectives/YYYY-MM-DD-bootstrap.md
   по retrospectives/TEMPLATE.md (что делали в сессии, что узнали).

8. Покажи мне:
   - 5-строчное summary что я получу.
   - Список ВСЕХ изменённых/созданных файлов.
   - Один конкретный первый шаг.

9. Остановись. Жди "да, поехали" прежде чем писать код.

Не коммить. Не push. Все ответы — на русском.
```

## Что должно получиться

- Заполнены все 7 блоков `business/` (с пометками где данных нет).
- Разделы 1, 2, 9 в `CLAUDE.md` обновлены, файл ≤ 200 строк.
- План `plans/YYYY-MM-DD-<имя>.md` с 10 рисками.
- Прогнана критика, правки внесены.
- Создана первая ретроспектива.
- Claude остановился и ждёт «да».
