# Промпт: план результата

> Используйте, когда нужна новая фича или крупное изменение, а плана ещё нет. Процесс - `docs/workflow.md`, разделы 4-5.

## Когда использовать

- Задача размера M или L: новая страница, интеграция, изменение схемы данных, многомодульная правка.
- Идея прояснена (например, после `grill-idea.md`), и пора описать весь путь до результата.

## Когда НЕ использовать

- S-задача: опечатка, цвет кнопки, ошибка типизации - делается без плана.
- Действующий план этого результата уже есть - его продолжают и дополняют.

## Промпт

```
Нужен план результата: <ЧТО ХОЧУ ПОЛУЧИТЬ, ОДНИМ ПРЕДЛОЖЕНИЕМ>.

1. Найди действующий план этого результата в plans/ и в документах архитектуры. Нашёл - покажи его и предложи дополнить, второй не создавай.
2. Прочитай ядро business/INDEX.md и файлы под задачу по .claude/rules/business-context.md, канонический документ архитектуры, docs/workflow.md (разделы 4-6).
3. Определи размер: S / M / L. S - скажи, что план не нужен, и предложи сразу сделать.
4. Создай plans/YYYY-MM-DD-<имя>.md по plans/TEMPLATE.md. Обязательно: критерий приёмки, границы и полномочия, лимиты, варианты в "Дизайне решений", 10 реальных причин провала, Challenge Loop, все фазы до результата с проверками.
5. Проведи ревью с судьёй по docs/prompts/run-critique.md - по норме docs/workflow.md, раздел 5: L - всегда, M - по умолчанию; пропуск для M - только при малом риске, с моего согласия, с датой, причиной и согласием в разделе 7. Поставь статус "на ревью".
6. Покажи итоговый план и попроси одобрения. Реализацию до одобрения не начинай.
```

## Что должно получиться

- Либо найден и дополнен действующий план, либо создан новый по шаблону.
- Решения судьи в разделе 7 плана или запись о пропуске ревью с датой, причиной и моим согласием.
- Claude ждёт одобрения; после него исполняет все фазы по `docs/workflow.md`, раздел 6.
