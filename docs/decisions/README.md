# Architecture Decision Records (ADR)

Здесь фиксируются нетривиальные технические и архитектурные решения. ADR — это маленький markdown-файл, который объясняет: что выбрали, почему, какие альтернативы отвергли.

## Зачем

Через 3 месяца никто не вспомнит, **почему** выбрали именно `drizzle`, а не `prisma`. ADR отвечает на этот вопрос за 30 секунд.

## Когда писать ADR

- Выбрали БД, ORM, аутентификацию, очередь, платежи.
- Решили разделить / объединить модули.
- Выбрали платформу деплоя.
- Принципиально поменяли подход (например, перешли с REST на tRPC).

Если решение тривиальное (выбрали Tailwind вместо CSS-in-JS — это уже зашито в стек) — ADR не нужен.

## Формат имени

`NNNN-короткое-имя.md`, где NNNN — порядковый номер, начиная с `0001`.

Пример: `0001-database-postgres-drizzle.md`.

Не удаляй ADR. Поменяй статус на `deprecated` или `superseded by ADR-NNNN` и в новом ADR сошлись на старый.
