# plans/ — планы фич

В этой папке живёт **текущая работа**: один план = одна функция.

## Правила

1. Имя файла: `YYYY-MM-DD-короткое-имя-фичи.md` (kebab-case, латиницей).
2. **Один план = одна функция**. Если план разрастается — раздели на два.
3. Используйте [`TEMPLATE.md`](./TEMPLATE.md) как стартер.
4. Обязателен блок «10 причин провала» — он не для красоты.
5. После каждой сессии обновляйте чекбоксы `[ ]` → `[x]` и блок «Итог».
6. Если план изменился по сути — переписывайте раздел «Дизайн решений», не дописывайте «P.S.».
7. Когда фича выкачена — план **не удаляется**. Архивируйте в `plans/archive/` если переполнено.

## Жизненный цикл плана

```
[draft]  →  [in-progress]  →  [done]  →  [archive]
   ↑           |                ↓
   |           └→ [blocked] ────┘
   └──────────── [cancelled]
```

Статус указывайте в шапке плана.

## Связь с retrospectives/

Каждый план в статусе `done` должен иметь хотя бы одну ретроспективу в `retrospectives/`. Сошлитесь на неё в блоке «Итог».
