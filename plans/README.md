# plans/ - планы результатов

Здесь живёт текущая работа и её память между сессиями: план результата с checkpoint. Процесс - `docs/workflow.md`, разделы 4-6.

## Правила

1. **Сначала найди действующий план** этого результата - здесь или внутри документов архитектуры. Нашёл - продолжай его, второй план не заводи.
2. **Один план - один согласованный результат:** несколько функций и фаз до готовности. Разные владельцы, сроки или критерии приёмки - разные планы.
3. Имя файла: `YYYY-MM-DD-короткое-имя.md`, латиницей, kebab-case. Основа - [`TEMPLATE.md`](./TEMPLATE.md).
4. До реализации - ревью с судьёй по норме `docs/workflow.md` (раздел 5: L - всегда, M - по умолчанию, пропуск при малом риске и с согласия пользователя), затем одобрение пользователя, записанное в шапке плана. Автор закончил план - статус «на ревью»; он держится до одобрения.
5. После одобрения агент проходит все фазы сам. `[x]` у фазы ставится только при проверенных критериях.
6. Checkpoint обновляется после каждой фазы и перед паузой. Новая сессия сначала сверяет его с файлами, diff и тестами.
7. Изменился подход - перепиши «Дизайн решений». Изменились объём или полномочия - нужно новое одобрение.
8. Завершённый план не удаляется. Папка переполнилась - перенеси старые планы в `plans/archive/`.

## Жизненный цикл

```
черновик → на ревью → одобрен → в работе → завершён → archive/
                                    ↓  ↑
                               заблокирован
любой статус → отменён (причина в «Итоге», урок в retrospectives/)
```

## Связь с retrospectives/

Закрытый план ссылается в «Итоге» на свою ретроспективу.
