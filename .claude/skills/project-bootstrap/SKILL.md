# Skill: project-bootstrap

Адаптация шаблона `smyslokod-starter` под новый проект пользователя. Параллель главного промпта из `START_HERE.md` — но запускается автоматически когда условия активации совпадают.

## Когда применять

Любое из условий:

1. Пользователь явно попросил «адаптировать шаблон» / «начать новый проект на этом шаблоне».
2. Файлы в `business/` всё ещё содержат пометки `> 🔲 заполнить при адаптации проекта`.
3. `CLAUDE.md` раздел «Что это за проект» содержит фразу «smyslokod-starter — стартовый шаблон» (значит, ещё не переписан).

## Что НЕ делать

- Не запускай этот скилл если `business/INDEX.md` уже переписан под конкретный проект.
- Не запускай в проекте, где есть активный план в `plans/` — пользователь уже работает.

## Какие файлы читать в начале

В таком порядке:

1. `CLAUDE.md`
2. `AGENTS.md` (если есть)
3. `business/INDEX.md`
4. `business/audience/avatar.md`
5. `business/products/overview.md`
6. `plans/TEMPLATE.md`
7. `retrospectives/TEMPLATE.md`
8. `.claude/rules/business-context.md`

После чтения скажи одной фразой что понял про текущее состояние шаблона.

## Какие вопросы задавать

По одному за раз. После каждого жди ответ. По возможности предлагай 3–4 варианта (а/б/в/г).

1. О каком проекте речь? (одно предложение)
2. Кто целевая аудитория? (один сегмент конкретно)
3. Какую боль вы снимаете? (одна боль)
4. Формат продукта: (а) лендинг + форма; (б) SaaS-приложение; (в) AI-агент / бот; (г) marketplace; (д) другое
5. Где будете деплоить: (а) Vercel; (б) Railway; (в) Amvera; (г) ещё не решили
6. Какой минимальный результат хотите за одну сессию? (одна фраза)
7. Есть ли бренд / тон / референсы? Если да — где взять
8. Какие интеграции точно нужны? (LLM, платежи, БД, аналитика)
9. Что стоп-критерий «хватит на сегодня»?
10. Что важно НЕ трогать?

## Как обновлять business/

После интервью обнови:

- `business/INDEX.md` — актуализируй карту, если меняется
- `business/company/about.md` — секция «Краткое описание»
- `business/products/overview.md` — секция «Один абзац для лендинга»
- `business/audience/avatar.md` — все блоки по ответам пользователя
- `business/goals/monthly.md` — главную цель и метрику
- `business/economics/unit-economics.md` — если применимо
- `business/marketing/channels.md` — если есть готовый канал
- `business/assets/brand-guidelines.md` — тон / цвета / эмодзи

**Если данных мало** — оставляй блоки `> 🔲 заполнить:` с конкретными вопросами. Не выдумывай факты.

## Как обновить CLAUDE.md

Перепиши только разделы:

- «1. Что это за проект» — под проект пользователя.
- «2. Стек» — если меняется.
- «9. Правила UI» — если есть бренд-референс.

Остальное не трогай. Файл должен оставаться ≤ 200 строк.

## Как создать первый план

Файл: `plans/YYYY-MM-DD-<короткое-имя>.md` (сегодняшняя дата). По шаблону `plans/TEMPLATE.md`. Цель плана = минимальный результат из вопроса 6.

В блоке «10 причин провала» — реальные риски этого конкретного проекта. Не общие слова.

## Как запустить критику

Используй субагент `critic` (`.claude/agents/critic.md`). Если по каким-то причинам субагенты недоступны — сделай критику сам по тому же формату. Внеси правки в план до того как покажешь пользователю.

## Что выдавать в конце

Перед остановкой:

1. 5-строчное summary что пользователь получит.
2. Список файлов, которые ты изменил/создал в результате этого скилла.
3. Один конкретный первый шаг кода или контента, который ты предлагаешь сделать на следующей итерации.

Затем **остановись**. Жди явное «да» от пользователя. Без него — никакого кода, никаких `pnpm install`, никаких коммитов.
