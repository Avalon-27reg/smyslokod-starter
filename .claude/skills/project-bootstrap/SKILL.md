# Skill: project-bootstrap

Адаптация шаблона `smyslokod-starter` под новый проект пользователя в **одном из трёх режимов** глубины. Параллель главного промпта из `START_HERE.md` — но запускается автоматически когда условия активации совпадают.

## Когда применять

Любое из условий:

1. Пользователь явно попросил «адаптировать шаблон» / «начать новый проект на этом шаблоне».
2. Файлы в `business/` всё ещё содержат пометки `> 🔲 заполнить при адаптации проекта`.
3. `CLAUDE.md` раздел «Что это за проект» содержит фразу «smyslokod-starter — стартовый шаблон» (значит, ещё не переписан).

## Когда НЕ применять

- `business/INDEX.md` уже переписан под конкретный проект.
- В `plans/` есть активный план — пользователь уже работает.

## Какие файлы читать в начале

В таком порядке:

1. `CLAUDE.md`
2. `AGENTS.md` (если есть)
3. `business/INDEX.md`
4. `business/audience/avatar.md`
5. `business/products/overview.md`
6. `plans/TEMPLATE.md`
7. `retrospectives/TEMPLATE.md`
8. `.claude/rules/business-context.md`

После чтения скажи одной фразой что понял про текущее состояние шаблона.

## Шаг 0. Auto-detect режима + выбор стека

Перед основным интервью задай **3 коротких вопроса**, чтобы выбрать глубину. По одному за раз.

1. **Опиши проект одним предложением и срок до первого пользователя.**
   Варианты срока: (а) 1–3 дня, (б) 1–4 недели, (в) 1–3 месяца, (г) 3+ месяца.

2. **Будут ли регистрация, платежи или сбор персональных данных?**
   Варианты: (а) ничего, чистый просмотр контента; (б) только email/имя; (в) платежи и/или ПДн.

3. **Сколько у тебя уже есть фактов про целевую аудиторию?**
   Варианты: (а) почти ничего, гипотеза; (б) общее представление; (в) реальные интервью или продажи.

### Правила выбора режима

| Сигналы | Режим |
| ------- | ----- |
| Срок < 1 недели **И** без платежей **И** аудитория = гипотеза | **MINIMAL** |
| Срок 1–4 недели **ИЛИ** только email/имя **ИЛИ** общее представление | **LITE** |
| Срок 1+ месяц **ИЛИ** платежи / ПДн **ИЛИ** реальные интервью | **FULL** |
| Сигналы конфликтуют (например: 3 дня но платежи) | Объясни конфликт пользователю и предложи **выбор словами**, рекомендуй на полшага выше |

**Всегда покажи** пользователю выбранный режим и обоснование одной строкой. Спроси: «подтверждаешь, или хочешь другой?». Пользователь может вручную переключить на любой режим.

Если пользователь зашёл по shortcut-промпту (`bootstrap-minimal.md` / `bootstrap-lite.md` / `bootstrap-full.md`) — пропусти выбор режима, иди сразу в выбранный режим.

### Выбор стека (после подтверждения режима)

Шаблон **не содержит предустановленного стека**. После того как режим подтверждён, задай один вопрос про стек:

> «Какой стек ставим для этого проекта?»
> (а) Next.js 15 + TypeScript + Tailwind + shadcn/ui (web-MVP / лендинг / SaaS)
> (б) Python + FastAPI / Django (бэкенд / API / админка)
> (в) Telegram-бот (aiogram на Python или Telegraf на Node)
> (г) Vite + React / Vue / Svelte (SPA без SSR)
> (д) React Native / Expo (мобильное)
> (е) Что-то другое — расскажи свободным текстом
> (ж) Без кода — это контент-проект / документация / методология

После ответа:

- Если (ж) — сразу переходи к интервью режима, не предлагай ставить ничего.
- Если (а)–(е) — **не ставь ничего сейчас**. Запиши выбор в `CLAUDE.md` раздел «2. Стек» (заменив текст про «не привязан к стеку»), и в `business/products/overview.md` — для контекста. Команды установки (`pnpm create next-app`, `pip install fastapi`, ...) выполнишь только после явного «да, поехали» в самом конце бутстрапа.

Это сохраняет наш принцип «никакого кода до подтверждения плана».

## Режим MINIMAL — для прототипа / лендинга / гипотезы

**Время:** 15–30 минут. **Вопросов:** 3–4. **Цель:** запустить первый видимый результат за 1–3 дня без бюрократии.

### Вопросы (по одному, с вариантами а/б/в/г)

1. **Что это и для кого?** Одно предложение в формате «<что> для <кого>, чтобы <боль>».
2. **Какой первый видимый результат хочешь получить за 1 сессию?** (одна фраза)
3. **Где будешь хостить:** (а) Vercel, (б) Railway, (в) Amvera, (г) пока локально?
4. **Что важно НЕ трогать?** (если ничего — пропустить)

### Что обновить в business/

Только эти 3 файла, минимально:

- `business/products/overview.md` — секция «Один абзац для лендинга» по ответу 1.
- `business/audience/avatar.md` — только блок «Кто это» (1–2 строки) и «Главная боль» (1 строка).
- `business/goals/monthly.md` — главная цель = ответ 2.

В остальных файлах оставь существующие пометки `> 🔲 заполнить:` с одной строкой «не нужно для прототипа, заполнить если проект перерастёт в LITE/FULL».

### Что обновить в CLAUDE.md

Только раздел «1. Что это за проект» — под новую идею. Остальное не трогай.

### Что создать дальше

- Один план в `plans/YYYY-MM-DD-<короткое-имя>.md` по `plans/TEMPLATE.md`. Минимальная фича = ответ 2.
- В блоке «10 причин провала» — 5 реальных рисков (для MINIMAL допускается 5 вместо 10).
- Critic — **опционально**. Если пользователь не просил, не запускай.

## Режим LITE — для MVP / стартапа на коленке

**Время:** 45–60 минут. **Вопросов:** 6–7. **Цель:** проект с понятной аудиторией, монетизацией и каналами на 1–4 недели.

### Вопросы (по одному, с вариантами а/б/в/г)

1. **О каком проекте речь?** (одна фраза)
2. **Кто целевая аудитория?** Один сегмент конкретно (роль + контекст).
3. **Какую боль снимаете?** Одна боль.
4. **Формат продукта:** (а) лендинг + форма; (б) SaaS-приложение; (в) AI-агент / бот; (г) marketplace; (д) другое.
5. **Монетизация:** (а) бесплатно / лидогенерация; (б) разовая оплата; (в) подписка; (г) ещё не знаю.
6. **Какие 1–2 канала привлечения** планируешь? (например: Instagram, SEO, рассылка, прямые продажи).
7. **Какой первый минимальный результат** хочешь увидеть за 1 сессию?

### Что обновить в business/

- `business/products/overview.md` — описание + формат + один абзац для лендинга.
- `business/products/pricing.md` — модель оплаты (если применимо).
- `business/audience/avatar.md` — все блоки по ответам 2–3.
- `business/audience/objections.md` — 3 главных возражения (если знаешь).
- `business/goals/monthly.md` — цель месяца + одна метрика.
- `business/marketing/channels.md` — 1–2 канала из ответа 6.
- `business/assets/brand-guidelines.md` — тон, цвета, эмодзи (мини-блок, если есть готовый бренд — иначе оставь `🔲 заполнить:`).

Не трогай: `economics/`, `company/legal.md`, `marketing/competitors.md`, `marketing/content.md` — оставь существующие пометки.

### Что обновить в CLAUDE.md

Разделы 1, 2 (стек если меняется), 9 (UI если есть бренд-референс).

### Что создать дальше

- Один план по `plans/TEMPLATE.md`, минимальный результат = ответ 7.
- Полный блок «10 причин провала» (10, не 5).
- Critic — **по желанию пользователя**.

## Режим FULL — для коммерческого продукта

**Время:** 90–120 минут. **Вопросов:** 10+. **Цель:** проект с экономикой, юр. контекстом, несколькими сегментами / продуктами, на 1+ месяцев.

### Вопросы (по одному, с вариантами а/б/в/г)

1. О каком проекте речь? Одна фраза.
2. Кто целевая аудитория? Один сегмент конкретно.
3. Какую боль снимаете? Одна боль.
4. Формат продукта: (а) лендинг + форма; (б) SaaS; (в) AI-агент / бот; (г) marketplace; (д) другое.
5. Где будете деплоить: (а) Vercel; (б) Railway; (в) Amvera; (г) ещё не решили.
6. Какой минимальный результат хотите за одну сессию? Одна фраза.
7. Есть ли бренд / тон / референсы? Если да — где взять.
8. Какие интеграции точно нужны? (LLM, платежи, БД, аналитика).
9. Что стоп-критерий «хватит на сегодня»?
10. Что важно НЕ трогать?

Дополнительно для FULL:

11. **Юрисдикция / есть ли ИП/ООО / собираете ли ПДн?**
12. **Базовая экономика:** какая цена и сколько примерно стоит привлечение клиента (хотя бы порядок)?
13. **Конкуренты:** 2–3 ближайших.

### Что обновить в business/

Все 7 блоков:

- `business/INDEX.md` — актуализируй карту.
- `business/company/about.md`, `company/team.md`, `company/legal.md`, `company/values.md`.
- `business/products/overview.md`, `products/pricing.md`, `products/product-1.md`.
- `business/audience/avatar.md`, `audience/segments.md`, `audience/objections.md`, `audience/journey.md`.
- `business/goals/annual.md`, `goals/quarterly.md`, `goals/monthly.md`, `goals/kpi.md`.
- `business/economics/unit-economics.md`, `economics/revenue.md`, `economics/costs.md`, `economics/forecast.md`.
- `business/marketing/channels.md`, `marketing/competitors.md`, `marketing/content.md`, `marketing/funnel.md`.
- `business/assets/brand-guidelines.md`, `assets/copy-bank.md`, `assets/testimonials.md`.

**Если данных мало** — оставляй блоки `> 🔲 заполнить:` с конкретными вопросами. Не выдумывай факты.

### Что обновить в CLAUDE.md

Разделы 1, 2, 9. Остальное не трогай. Файл должен оставаться ≤ 200 строк.

### Что создать дальше

- План по `plans/TEMPLATE.md` с полным блоком «10 причин провала».
- Прогон через субагент `critic` — **обязательно**.
- Первая запись в `retrospectives/` — **обязательно**, по `retrospectives/TEMPLATE.md`.

## Что выдавать в конце (общее для всех режимов)

Перед остановкой:

1. **Какой режим выбран** и почему (одна строка).
2. **5-строчное summary** что пользователь получит на выходе.
3. **Список файлов**, которые ты изменил/создал.
4. **Один конкретный первый шаг** кода или контента, который ты предлагаешь сделать на следующей итерации.

Затем **остановись**. Жди явное «да» от пользователя. Без него — никакого кода, никаких `pnpm install`, никаких коммитов.

## Антипаттерны во всех режимах

- Не выдумывай факты. Если не знаешь — пометка `🔲 заполнить:`.
- Не задавай 5 вопросов одним сообщением. По одному.
- Не запускай Critic если пользователь явно сказал «быстро» (только в FULL обязательно).
- Не уходи в технические детали стека до того как ясна цель.
- Не делай auto-detect молча — всегда покажи выбор и обоснование, дай переопределить.
