# Правила планирования

## Принципы

1. **Одна задача за раз.** Не начинай вторую фичу пока первая не дошла до ретроспективы.
2. **Один план = одна функция.** Если план разрастается — разделяй.
3. **Без плана не пишем код для крупной фичи.** Мелкая правка (опечатка, иконка, копи-правка) — без плана.
4. **Критика обязательна.** В каждом плане — блок «10 причин провала». Не 3, не 5 — десять.

## Что считается «крупной фичей»

Любое из:

- Новый раздел / страница приложения.
- Интеграция с внешним сервисом.
- Изменение схемы БД.
- Новый модуль > 200 строк.
- Что-то, что меняет user-flow.

Если все «нет» — пишем сразу, без плана. Но всё равно обновляем `business/` если узнали новое.

## Структура плана

См. `plans/TEMPLATE.md`. Главные блоки:

1. Цель — одно предложение.
2. Контекст — на какую цель из `business/goals/monthly.md` работает.
3. Дизайн решений — почему выбран этот путь.
4. Фазы с чекбоксами.
5. **10 причин провала + митигации.**
6. Критика плана.
7. Что НЕ входит в план.
8. Метрика успеха.
9. Итог (заполняется в конце).

## После каждой сессии

1. Обнови чекбоксы `[ ]` → `[x]` в активном плане.
2. Если изменился подход — перепиши «Дизайн решений», не дописывай постфактум.
3. Создай ретроспективу в `retrospectives/`.
4. Если возникли новые риски — добавь в «10 причин провала».

## Когда план закрывается

План в статусе `done` когда:

- Все фазы [x].
- Метрика успеха достигнута (или явно отмечено что не достигнута и почему).
- Есть запись в `retrospectives/` с пометкой «Решено: да».

## Когда план отменяется

- Цель потеряла смысл (приоритеты бизнеса сменились).
- Не работает ни один из вариантов решения.
- Стоимость оказалась несоизмерима с пользой.

В этом случае статус `cancelled` + короткое объяснение в «Итог» + урок в `retrospectives/`.

## Антипаттерны

- План на 50 фаз. → разделяй на отдельные планы.
- План без метрики успеха. → возвращаем на доработку.
- 10 причин провала в стиле «всё может пойти не так». → переделать в конкретные риски.
- Один план для двух функций. → разделяй.
- План без указания на цель из `goals/monthly.md`. → не приступать к коду.
