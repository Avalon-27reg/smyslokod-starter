# Правила UI и дизайна

> Эти правила применяются к любому UI-стеку (React+Tailwind, Vue, Svelte, Flutter, нативный HTML/CSS, Telegram-бот, веб-компоненты — что угодно). Конкретные технологии — выбор пользователя на старте, в скилле `project-bootstrap`.

## Главное правило

**Никакого generic AI-design.** Серый фон + синяя кнопка + emoji в заголовках + «Welcome to your dashboard» — запрещено по умолчанию.

## Перед версткой — ОБЯЗАТЕЛЬНО

1. Открой `business/assets/brand-guidelines.md`. Если пуст — спроси пользователя:
   - Тон (профессиональный / дружеский / экспертный / ироничный)
   - Цвета (можно одним предложением: «зелёно-чёрный, как у Stripe»)
   - Шрифт
   - Уровень формальности (на «вы» / на «ты»)
   - Эмодзи: да / нет / умеренно
2. Открой `business/audience/avatar.md`. Понимание ЦА → понимание UI.
3. Если пользователь дал референсы (скриншоты, ссылки на сайты) — изучи их перед версткой.

## Работа с референсами

- Скриншоты конкурентов / нравящихся сайтов — спрашивай у пользователя если их нет.
- Не копируй пиксель-в-пиксель. Бери идею расположения / иерархии / тон.
- Сошлись на референс в коммит-сообщении: «feat: лендинг — макет в духе X».

## Используй компонентную базу выбранного стека

Не пиши свои стили там, где есть готовый компонент:

- **React + Tailwind** → shadcn/ui (`pnpm dlx shadcn@latest add <component>`).
- **Vue** → shadcn-vue или PrimeVue.
- **Svelte** → shadcn-svelte или Skeleton.
- **Mobile (React Native)** → React Native Paper / Tamagui.
- **HTML/CSS без фреймворка** → Pico.css / Open Props.

Если кастомизируешь компонент — делай обёртку, не правь файлы библиотеки напрямую.

## CSS / стили

- Если выбран Tailwind — utility-first, не пиши `.css` файлы кроме `globals.css`.
- Если стек без Tailwind — используй CSS-переменные для тем, не хардкодь цвета.
- Не используй inline `style={...}` для статичных значений (если есть утилиты — используй их).
- Динамические значения — через inline `style` допустимо.
- Темы (light/dark) — через CSS-переменные, не через два набора классов.

## Адаптивность

- **Mobile-first.** Базовые стили — для < 640px.
- Брейкпоинты по умолчанию: `sm: 640`, `md: 768`, `lg: 1024`, `xl: 1280` (адаптируй под свой фреймворк).
- Проверяй на 360px, 768px, 1280px минимум.
- Кнопки и кликабельные зоны — минимум 44px высотой на мобильном.

## Доступность (a11y)

- `<button>` для кнопок, `<a>` для ссылок. Не путать.
- Все интерактивные элементы — с `aria-label` если иконка без текста.
- Цветовой контраст ≥ 4.5:1 для текста, ≥ 3:1 для крупного текста.
- Фокус-стили не убираем (`outline-none` без замены — нельзя).
- Изображения — с осмысленным `alt`.

## Микрокопия

- Не «Submit». Пиши «Записаться», «Отправить заявку», «Купить за 990 ₽».
- Не «Welcome to our app». Пиши то, что произойдёт за следующие 3 секунды.
- Тон копи берётся из `business/assets/brand-guidelines.md`.

## Иконки

- Веб: `lucide-react` / `lucide` — основной набор для большинства фреймворков.
- Native: системные иконки или Phosphor Icons.
- Не вставляй emoji вместо иконок если не разрешено в гайдлайнах.
- Размер иконок согласован с типографикой: 16px (рядом с body), 20px (header), 24px (CTA).

## Антипаттерны

- 5 кнопок одинакового размера и веса на странице — нет иерархии.
- Hero-секция без понятного оффера и без CTA.
- «Сделано на Next.js / Vue / Svelte» — не стоит хвастаться стеком, пользователю это не важно.
- Бесконечные градиенты, анимации частиц, glow-эффекты без причины.
- Стоковые фото с handshake / smiling-team — не использовать.

## Перед сдачей UI

- [ ] Открыл на 360px ширины.
- [ ] Открыл на 1280px ширины.
- [ ] Проверил dark-mode (если включён в проекте).
- [ ] Проверил клавиатурную навигацию (Tab, Enter, Esc).
- [ ] Проверил состояния: hover, focus, active, disabled, loading, error, empty.
- [ ] Проверил тексты: тон совпадает с `brand-guidelines.md`.
