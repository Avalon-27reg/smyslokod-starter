# Правила Git

## Когда коммитить

- После завершения **одной** логически целой части работы (одна фаза плана / один файл фичи / одна правка бага).
- Перед началом крупного рефакторинга — фиксируй текущее состояние.
- Перед опасной командой (миграция БД, переименование пакетов).
- В конце сессии — обязательно, даже если работа не завершена (с пометкой `wip:`).

## Формат сообщения

`<тип>: <краткое описание в нижнем регистре, без точки в конце>`

Типы:

- `feat` — новая функциональность
- `fix` — исправление бага
- `docs` — изменения только в документации
- `refactor` — рефакторинг без изменения поведения
- `chore` — сборка, конфиги, зависимости
- `test` — тесты
- `wip` — незавершённая работа (для конца сессии)
- `style` — форматирование, без изменения смысла

Примеры:

```
feat: добавлен лендинг главной страницы
fix: исправлен расчёт LTV в калькуляторе
docs: обновлён CLAUDE.md под новый проект
chore: обновлена версия Next.js до 15.1
wip: начат план для интеграции с Telegram
```

Если меняли несколько файлов из разных тем — это **два коммита**, не один.

## Что НЕ делаем

- `git add -A` / `git add .` без необходимости. Стейджим конкретные файлы. Иначе можно случайно закоммитить `.env`, кэши, временные файлы.
- `git commit -m "wip"` без описания — всегда указываем что именно wip.
- `git push --force` / `--force-with-lease` без явного «да» от пользователя.
- `git reset --hard` без явного «да». Это уничтожает работу.
- `git rebase` интерактивный — Claude Code не умеет в интерактивный ввод, может сломать историю.
- Коммит секретов (см. `security.md`).

## Push

- **Никогда** не делай `git push` без явного «да» от пользователя.
- Push в `main` / `master` — всегда обсуждаем.
- Push в feature-ветку — допустимо после `pnpm preflight` и явного согласия.

## Откат изменений

| Ситуация | Команда | Опасно? |
| -------- | ------- | ------- |
| Откатить незакоммиченный файл | `git restore <файл>` | нет |
| Убрать из стейджа | `git restore --staged <файл>` | нет |
| Отменить последний коммит, оставив изменения | `git reset --soft HEAD~1` | нет |
| Безопасный откат запушенного коммита | `git revert <hash>` | нет |
| Жёсткий сброс к коммиту | `git reset --hard <hash>` | **да, согласовывать** |
| Очистить untracked файлы | `git clean -fd` | **да, согласовывать** |

## Ветки

- `main` — стабильная, деплой-готовая.
- `feature/<имя>` — фичи.
- `fix/<имя>` — баги.
- `wip/<имя>` — экспериментальное.

## Pre-commit хуки

Если в проекте подключён husky / lint-staged — **не отключай их флагом `--no-verify`** без согласования. Пройди проверку: исправь lint и попробуй снова.

## Что делать если что-то пошло не так

1. Не паниковать. Git почти всё помнит.
2. `git reflog` показывает все HEAD за последние 90 дней.
3. Прежде чем что-то «чинить» — покажи пользователю текущее состояние и спроси.
