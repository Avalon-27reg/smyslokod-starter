# Правила деплоя

## Выбор платформы

| Платформа | Когда выбираем | Когда НЕ выбираем |
| --------- | -------------- | ------------------ |
| **Vercel** | простой Next.js сайт / лендинг / SaaS без особых требований к локации | ПДн российских пользователей и нужно соответствие 152-ФЗ |
| **Railway** | международный продукт с бэкендом и БД, Docker-ready | для лендинга — оверкилл |
| **Amvera** | российские пользователи, ПДн, требуется размещение в РФ | работа с международной аудиторией без RU-привязки |

Подробные инструкции:

- [docs/deployment/vercel.md](../../docs/deployment/vercel.md)
- [docs/deployment/railway.md](../../docs/deployment/railway.md)
- [docs/deployment/amvera.md](../../docs/deployment/amvera.md)

## Жёсткие правила

1. **Все секреты — только через Environment Variables хостинга.** Не в репо. Не в коде. Не в build-args.
2. **Перед прод-деплоем — `pnpm preflight`** (`pnpm lint && pnpm build`). Если падает — не деплоим.
3. **Сначала preview, потом production.** Vercel/Railway сами создают preview-деплои на pull request — пользуйся.
4. **Не делай прод-деплой в пятницу вечером и в ночь** без явной причины. Ставь deploy lock на это время если есть аналитика инцидентов.
5. **После деплоя — проверь.** Открой главную, проверь основной user-flow, проверь логи на ошибки.

## Чек-лист перед первым прод-деплоем

- [ ] `.env.example` актуален и совпадает с тем, что нужно прод-окружению.
- [ ] Все переменные окружения заведены на хостинге.
- [ ] `NEXT_PUBLIC_APP_URL` указывает на прод-домен, не на localhost.
- [ ] Источники изображений добавлены в `next.config.ts` `images.remotePatterns`.
- [ ] Проверена работа `pnpm build` локально.
- [ ] Проверена работа `pnpm start` локально (это запускает прод-сборку).
- [ ] Включён HTTPS (на хостингах включён по умолчанию).
- [ ] Аналитика подключена (если используется).
- [ ] Sentry / логи ошибок подключены (если используется).
- [ ] Health check endpoint существует (`/api/health` возвращает 200).

## Откат деплоя

- **Vercel:** в дашборде «Deployments» → выбираем предыдущий → «Promote to Production». Безопасно.
- **Railway:** в Deployments → Redeploy от старого коммита.
- **Amvera:** через панель управления, обычно через rollback в UI.

Не делайте откат через `git revert` + новый деплой — это медленнее. Используйте rollback хостинга.

## Логи и мониторинг

- Прод-логи смотрим только через хостинг. Не пишите `console.log` секретов.
- Алерты на 500-е ошибки — обязательно.
- Замер uptime — обязателен для прод-проектов с пользователями.

## Особые случаи

### Российские пользователи и 152-ФЗ

Если собираете ПДн (имя, email, телефон) пользователей из РФ:

- Хостинг — **только в РФ** (Amvera, Selectel, Yandex Cloud, VK Cloud).
- Зарегистрировать оператора ПДн в Роскомнадзоре.
- На сайте — Политика конфиденциальности и форма согласия на обработку ПДн.
- Уведомление об использовании Cookies.

См. `business/company/legal.md` и `docs/deployment/amvera.md`.

### Платежи

- Боевой эквайринг — только через Юр. лицо / ИП с подключённым РКО.
- В тестовой среде — только тестовые ключи.
- Webhook от платёжного провайдера — обязательно валидируем подпись.
- См. `.env.example` → `PAYMENT_PROVIDER`, `PAYMENT_SECRET_KEY`, `WEBHOOK_SECRET`.
