# CLAUDE.md — карта проекта для Claude Code

> Этот файл Claude Code читает первым в каждой сессии. Держите его ≤ 200 строк.
> Подробности уносите в `business/`, `docs/`, `.claude/rules/`.

## 1. Что это за проект

`smyslokod-starter` — стартовый шаблон для смысло-кодинга. Цель пользователя при адаптации: не «написать код», а **зафиксировать смысл** проекта в репозитории и потом превращать его в код.

Если этот файл ещё не переписан под конкретный проект — значит шаблон только что развернули. См. `START_HERE.md`.

## 2. Стек

Шаблон **стек-агностичный**. Никакого предустановленного фреймворка / языка нет. Стек выбирается на старте проекта (через скилл `project-bootstrap`) или явно пользователем.

Если этот раздел ещё не переписан под конкретный стек — значит шаблон только что развернули. После выбора пользователем здесь появится конкретика: язык, фреймворк, менеджер пакетов, линтер, деплой.

Поддерживаемые платформы деплоя (документация уже есть): Vercel / Railway / Amvera (см. `docs/deployment/`).

## 3. Структура репозитория

```
business/               # «мозг» проекта — бизнес-контекст, читается ВЫБОРОЧНО
plans/                  # планы фич, один план = одна функция
retrospectives/         # итог каждой завершённой сессии
docs/                   # архитектура, ADR, деплой, готовые промпты
.claude/                # правила, агенты, скиллы для Claude Code
.githooks/              # pre-push (защита main) + pre-commit (блок секретов)
.vscode/                # настройки IDE
.devcontainer/          # контейнерная среда (опционально)
scripts/                # doctor / install-hooks (sh + ps1)
```

После выбора стека пользователем в репо появятся: код приложения (например, `src/`), конфиги стека (например, `package.json`), и обновится `.gitignore`.

## 4. Работа с business/

- Это не «папка с заметками», это **источник истины** о проекте.
- **Не загружай весь business/ сразу.** В `business/INDEX.md` — карта.
- Перед задачей по продукту/тексту/UI/цене — открой только нужный файл из карты.
- Когда узнал новое о проекте — обнови соответствующий файл, **не складывай в conversation memory**.

Минимум перед стартом любой бизнес-задачи: `business/INDEX.md` + `business/audience/avatar.md` + `business/products/overview.md`.

## 5. Работа с plans/

- Перед любой крупной фичей создай `plans/YYYY-MM-DD-короткое-имя-функции.md` по `plans/TEMPLATE.md`.
- Прикинь размер задачи: **S** (багфикс — без плана), **M** (фича — план), **L** (крупное — план + Impact Analysis). Подробнее в `.claude/rules/planning.md`.
- **Один план = одна функция.** Если план разрастается — раздели.
- В плане обязательны: блок **«10 причин провала»**, **Challenge Loop** перед кодом, **Self-Audit** после реализации.
- После каждой сессии обнови чекбоксы `[ ]` → `[x]` и перепиши «Итог».
- Если план изменился по сути — обнови раздел «Дизайн решений», не дописывай постфактум.

## 6. Работа с retrospectives/

- В конце каждой сессии создавай `retrospectives/YYYY-MM-DD-короткое-имя.md` по `retrospectives/TEMPLATE.md`.
- Формат: задача → как решали → было / стало → решено? → что запомнить → что можно было лучше.
- Это **не отчёт начальству**, это память для будущих сессий.

## 7. Правила безопасности

- **Не читай `.env` и `.env.*` целиком.** Если нужно одно значение — спроси у пользователя или прочитай конкретную строку.
- **Не хардкодь секреты, токены, ключи.** Только через `process.env`.
- **Не печатай содержимое секретов в чат / в код / в логи.**
- **Не запускай команды с секретами в одной строке** (`curl -H "Authorization: $TOKEN" ...` — нет, через переменную env).
- Подробнее: `.claude/rules/security.md`.

## 8. Правила Git

- Коммиты — частые, маленькие, осмысленные. Формат: `тип: краткое описание` (feat/fix/docs/refactor/chore/test).
- **Никогда не делай `git push`, `git push --force`, `git reset --hard`, `git rebase` без явного `да` от пользователя.**
- Не используй `git add -A` без необходимости — стейджи только нужное.
- Откат: `git restore <файл>` / `git revert <hash>`. `git reset --hard` — последнее средство и только с разрешения.
- Подробнее: `.claude/rules/git.md`.

## 9. Правила UI

- Не делай «generic AI-design». Сначала спроси/прочитай референсы.
- Перед версткой — открой `business/assets/brand-guidelines.md`. Если файл пуст — спроси про тон, цвета, шрифты.
- Если в проекте есть UI-стек (React/Tailwind/shadcn, Vue, Svelte и т.д.) — используй его компонентную базу, не пиши свои стили там, где есть готовое.
- Проверяй mobile (≤ 640px) и desktop (≥ 1024px). Mobile — приоритет.
- Подробнее: `.claude/rules/ui-design.md`.

## 10. Формат завершения каждой сессии

В конце КАЖДОЙ сессии Claude обязан:

1. Обновить чекбоксы в активном `plans/<...>.md`.
2. Создать запись в `retrospectives/YYYY-MM-DD-<имя>.md`.
3. Если узнал что-то про проект — обновить нужный файл в `business/`.
4. Показать пользователю: «что сделано», «что не доделано», «следующий шаг».
5. **Не делать** `git commit` без согласования. **Не делать** `git push` никогда без явного «да».

## 11. Принципы кодинга и Anti-Rationalization

- 4 базовых принципа (думай → простота → хирургические правки → цель → проверка) лежат в `.claude/rules/coding-principles.md`. **Применяются всегда.**
- При незавершённой работе **запрещено** оправдания типа «pre-existing», «out of scope», «доделаем потом», «всё кроме X сделано». Если что-то не сделано — это **не сделано**, говори честно. Если нужна отдельная задача — заводи её отдельно.
- Перед заявлением «готово» прогони Self-Audit из плана.
