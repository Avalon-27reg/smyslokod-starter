# START_HERE - первый запуск шаблона

Откройте папку проекта в VS Code, запустите Claude Code (или Codex) и напишите одной-двумя фразами, с чем пришли:

- **«Хочу что-то сделать, идеи пока нет»** - Claude поможет найти направление и дешёвую проверку спроса.
- **«У меня идея: ...»** - заполнит ядро бизнес-контекста из ваших слов, спросит только недостающее и предложит план.
- **«Есть код»** или **«есть документ архитектуры»** - изучит его, отделит сделанное от обещанного и предложит следующий шаг.
- **«Продолжаем»** - найдёт активный план, сверит его checkpoint с файлами и продолжит.

Можно просто написать «привет»: Claude увидит, что шаблон ещё не адаптирован, и спросит сам.

---

## Что произойдёт при старте с идеи

1. Claude спросит, приватный ли репозиторий. Для публичного он уберёт `business/` из git до того, как туда попадут ваши бизнес-данные.
2. Заполнит ядро `business/INDEX.md` из ваших слов и спросит недостающее - по одному вопросу, с вариантами ответа.
3. Предложит глубину и объяснит выбор:
   - **MINIMAL** - лендинг, прототип, гипотеза на 1-3 дня;
   - **LITE** - MVP, один продукт и одна аудитория;
   - **FULL** - коммерческий продукт с платежами, персональными данными или командой.
   Можно выбрать самому словами: «минимально», «по-полной».
4. В LITE и FULL посередине будет **Reality Check** - 2-3 риска идеи, которые стоит закрыть.
5. Спросит стек и запишет его. Ничего не установит до одобрения плана.
6. Напишет первый план результата. Первая фаза - минимальный сквозной сценарий через реальные слои, а не заглушка. План пройдёт независимое ревью с судьёй; для небольшого плана с малым риском ревью можно пропустить с вашего согласия.
7. Покажет план и попросит одобрения. После одобрения Claude проходит все фазы сам - тест, код, проверки, ревью, checkpoint - и останавливается на лимитах, блокерах и действиях, которым нужно ваше отдельное «да»: push, деплой, платежи, внешние публикации.

**Прервались посередине** - в следующий раз напишите «продолжаем». Отдельного журнала нет: Claude восстановит состояние по ядру `business/INDEX.md` и плану.

**Чтобы одобренный план шёл без остановок на каждую правку**, включите в Claude Code режим принятия правок (Shift+Tab, пока внизу не появится «accept edits») и на повторяющиеся безопасные команды - тесты, линтер, сборку - отвечайте «Yes, and don't ask again». Запросы на commit, push и опасные команды останутся: это защита, а не помеха. Bypass Permissions для этого не нужен.

## Если Claude не начал сам

````
Прочитай CLAUDE.md и docs/workflow.md. Выбери вход по разделу 1 процесса и веди работу по нему.

Что у меня есть: <идея / код / документ архитектуры / ничего>.

Работай по-русски, один вопрос за раз, только о том, что меняет ближайшее решение. Код и установку зависимостей начинай после моего одобрения плана.
````

## После старта

Запустите доктор - он проверит, что методология на месте и git-хуки активированы:

```bash
pwsh scripts/doctor.ps1   # Windows
# или
bash scripts/doctor.sh    # macOS / Linux / WSL / Git Bash
```

Дальше работаете обычно: в начале сессии - «продолжаем» (`docs/prompts/start-session.md`), в конце - `docs/prompts/end-session.md`, между ними - нужный промпт из `docs/prompts/INDEX.md`.
