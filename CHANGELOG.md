# Changelog

Значимые изменения шаблона. Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) + semver.

## [2.0.0] - 2026-10-21

Процесс перестроен по логике [claude-code-starter](https://github.com/artemiimillier/claude-code-starter) v1.1.0 (MIT, 11.09.2026); сохранены агенты, правила, хуки, размеры S/M/L, 10 причин провала, Challenge Loop и Self-Audit этого шаблона. Тексты написаны заново.

### Добавлено
- **`docs/workflow.md`** - единственный источник процесса для Claude Code и Codex: старт по фактам, второй мозг, архитектура, план, ревью с судьёй, исполнение, 4 пункта перед push, границы полномочий, завершение. `CLAUDE.md` подключает его импортом, `AGENTS.md` ссылается на него.
- **Старт от того, что есть:** нет идеи / идея / архитектура / код / продолжаем. Вопросы - только о пробелах, которые меняют ближайшее решение.
- **Ядро `business/INDEX.md`:** проект, аудитория, проблема, цель и критерий, ограничения, тип проекта, приватность, факты, гипотезы, открытые вопросы.
- **Агент `judge`:** решение принять / отклонить / отложить по каждой находке рецензентов, с причиной и источником.
- **Исполнение одобренного плана целиком:** тест до кода, проверки стека, независимое ревью, судья, checkpoint; остановка на лимитах, блокерах и действиях, которым нужно отдельное «да».
- **Проверка приватности до первой записи** бизнес-данных: порядок в `.claude/rules/security.md`.
- **Проверка перед push, merge и деплоем** по 4 пунктам: регрессия, side effects, think ahead, совместимость; не проверено = красное.
- **Режим IMPORT** для проекта с кодом или документом архитектуры; **некоммерческий проект** без выдуманных продаж; **Reality Check** в LITE и FULL.
- **`CONTEXT.md`** - словарь терминов; промпты `import-existing-project.md`, `stress-test.md`, `install-skill-safely.md`.

### Изменено
- **Один план - один результат**, а не одна функция. План несёт границы и полномочия, лимиты, ревью и судью, одобрение, checkpoint и итоговую приёмку (`plans/TEMPLATE.md`).
- **Формы `business/` переехали в `templates/business/`.** В свежей копии `business/` содержит только ядро; файл раздела появляется по тому же пути, когда для него есть данные.
- `project-bootstrap`: глубина MINIMAL / LITE / FULL выбирается по риску и задаёт, какие разделы создавать; первый план - на одобрение.
- `run-critique.md`: рецензенты по риску и судья вместо одного `critic`; без субагентов - порядок по сессиям.
- `architect` готовит текст ADR, файл пишет основной агент: рецензент в репозиторий не пишет.
- `start-session.md` - вход «продолжаем» со сверкой checkpoint; `end-session.md` - обновление checkpoint, ретроспектива при уроке.
- `CLAUDE.md` - короткая карта проекта; `AGENTS.md` - вход для Codex без пересказа правил.

### Удалено
- `.claude/rules/planning.md` - содержимое в `docs/workflow.md` (раздел 4) и `plans/TEMPLATE.md`.
- Промпты `bootstrap-minimal.md`, `bootstrap-lite.md`, `bootstrap-full.md`: глубина задаётся словами при старте.
- Собственные план и ретроспектива шаблона от 03.05.2026: в проекте пользователя агент принял бы их за действующий план. История - в git.

### Совместимость
Проект на версии 1.x продолжает работать по своим файлам. Переход на 2.0 - вручную, по шагам; свои правки в этих файлах сохраняйте слиянием, а не перезаписью.

1. **Процесс и карта.** Скопируйте `docs/workflow.md` и `AGENTS.md`. В новый `CLAUDE.md` перенесите свои разделы 1-2; строка `@docs/workflow.md` в нём обязательна.
2. **Правила.** Слейте `.claude/rules/` из 2.0 со своими правками. Удалите `.claude/rules/planning.md`: Claude Code подгружает все файлы `.claude/rules/`, и старое правило «один план = одна функция» спорило бы с новым процессом.
3. **Агенты, скиллы, промпты.** Скопируйте `.claude/agents/` (новый `judge`, режим ревью у остальных), `.claude/skills/project-bootstrap/` (старый пишет в `business/` без проверки приватности), `docs/prompts/` (старый `run-critique.md` допускал самопроверку), `plans/TEMPLATE.md` и `plans/README.md`, `scripts/doctor.*`.
4. **Бизнес-контекст.** Скопируйте `templates/business/` и `CONTEXT.md`. Заполненные файлы `business/` оставьте на месте - пути не изменились; пустые формы удалите. Ядро `business/INDEX.md` из 2.0 заполните по своим файлам.
5. **Приватность.** `business/` уже в git публичного репозитория - он в истории, `.gitignore` его оттуда не уберёт. Пройдите проверку из `.claude/rules/security.md`; секреты из истории удаляются отдельно (`git filter-repo`) и с ротацией ключей.
6. **Планы.** Действующие планы дозаполните разделами «Границы и полномочия» и «Checkpoint» и строкой «Одобрение» в шапке. Статусы переведите: `draft` → черновик, `in-progress` → в работе, `blocked` → заблокирован, `done` → завершён, `cancelled` → отменён.
