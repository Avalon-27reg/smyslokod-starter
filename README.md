# smyslokod-starter

Стартовый шаблон для **смысло-кодинга** - методологии, при которой смысл проекта живёт в репозитории рядом с кодом. Бизнес-контекст, план, правила и готовые промпты лежат в markdown-файлах, и Claude Code или Codex читают их, прежде чем что-либо менять.

**Стек-агностично.** Шаблон не привязан к Next.js, Python, боту или mobile. Стек выбирается на старте, методология уже на месте.

**Один процесс для двух агентов.** `docs/workflow.md` - единственный источник процесса: Claude Code подгружает его через `CLAUDE.md`, Codex читает по ссылке из `AGENTS.md`.

## Кому подходит

- Основатель или соло-разработчик, которому нужно, чтобы AI-агент действовал в рамках бизнес-контекста.
- Команда, которая хочет хранить бизнес-знания в Git, а не в Notion.
- Тот, кто работает попеременно в Claude Code и Codex: процесс у обоих один.
- Тот, кто устал объяснять агенту одно и то же в каждой сессии.

**Это НЕ:**

- Готовая SaaS-платформа.
- Аналог `create-next-app`: привязки к стеку нет, только методология и обвязка.

## Быстрый старт

```bash
# 1. Клонировать
git clone https://github.com/Avalon-27reg/smyslokod-starter.git my-project
cd my-project

# 2. Включить git-хуки (защита main + блок секретов)
bash scripts/install-hooks.sh        # macOS / Linux / Git Bash / WSL
pwsh scripts/install-hooks.ps1       # Windows PowerShell

# 3. Открыть в VS Code
code .
```

4. В Claude Code (или Codex) напишите, с чем пришли:
   - «хочу что-то сделать, идеи пока нет»;
   - «у меня идея: ...»;
   - «есть код» или «есть документ архитектуры»;
   - «продолжаем».

Обязательной анкеты нет: агент заполняет ядро из ваших слов и спрашивает только то, что меняет ближайшее решение. Глубину бизнес-контекста (MINIMAL / LITE / FULL) он предложит по риску проекта, её можно сменить словами. Подробно - [START_HERE.md](./START_HERE.md).

## Как идёт работа

```mermaid
flowchart LR
    Start[С чем пришли:<br/>идея, код,<br/>архитектура]
    Core[Ядро business/INDEX.md<br/>приватность проверена]
    Plan[План результата<br/>в plans/]
    Review[Ревью<br/>и судья]
    OK{Одобрено?}
    Phase[Фаза: тест, код,<br/>проверки, ревью, судья]
    CP[Checkpoint<br/>в плане]
    Gate[4 пункта<br/>перед push]
    Done[Приёмка<br/>и ретроспектива]

    Start --> Core --> Plan --> Review --> OK
    OK -- правки --> Plan
    OK -- да --> Phase --> CP
    CP -- следующая фаза --> Phase
    CP -- все фазы --> Gate --> Done
```

1. **Старт по фактам.** Агент определяет вход - нет идеи, идея, архитектура, код или продолжение - и предлагает ближайший полезный шаг.
2. **Второй мозг по мере данных.** Сначала ядро `business/INDEX.md`. Файл раздела создаётся из формы, когда появились факты. Приватность репозитория проверяется до первой записи.
3. **Один план на результат.** План описывает весь путь до результата, проходит независимое ревью, судья решает по каждой находке. План одобряет пользователь.
4. **Исполнение без лишних остановок.** После одобрения агент проходит все фазы сам: тест до кода, проверки стека, независимое ревью, судья, checkpoint. Он останавливается на лимитах, блокерах и действиях, которым нужно отдельное «да»: push, деплой, платежи, внешние публикации.
5. **Продолжение после паузы.** «Продолжаем» - агент сверяет checkpoint плана с файлами, diff и тестами и идёт дальше.

## Безопасность

- Запрет на чтение `.env*` в `.claude/settings.json`: Claude Code не прочитает их, даже если попросить.
- Pre-commit хук блокирует коммит `.env`, `*.pem`, `*.key` и строк, похожих на API-ключи (OpenAI / Anthropic / AWS / GitHub / Google / Slack / JWT).
- Pre-push хук блокирует force-push и удаление веток `main` / `master`.
- `git push`, `git push --force`, `git reset --hard`, `git rebase`, `rm -rf` - только после явного «да» пользователя (`.claude/rules/git.md`, `.claude/rules/security.md`).
- Приватность репозитория проверяется до первой записи бизнес-данных: в публичном репозитории `business/` уходит из git.
- Перед push, merge и деплоем - вердикт по 4 пунктам: регрессия, side effects, think ahead, совместимость. Не проверено = красное.
- Одобренный план не даёт прав на деплой, платежи, внешние публикации и установку расширений: для них нужно отдельное «да».
- Скилл, MCP или пакет из непроверенного источника ставится только после чтения исходников по `docs/prompts/install-skill-safely.md`.
